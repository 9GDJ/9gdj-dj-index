# 9GDJ DJ Index

纯静态 GitHub Pages 站点：索引**互联网公开列表**中的舞曲曲目元数据，按**单曲/串烧**、**中文/英文**分类，支持搜索、日期归档、页内试听与一键下载。

> 本项目仅抓取和展示公开列表中的**元数据**（文件名、大小、入库时间、来源链接），**不下载、不存储、不转存任何音频文件**。站内「试听/下载」由边缘代理层按需实时转发音频流（不缓存、不落盘），访问者**免登录**自动获得试听/下载权限。

## 在线站点

**https://9gdj.com/9gdj-dj-index/**

## 核心架构

```
┌─────────────────┐      ┌───────────────────┐      ┌──────────────────┐
│  GitHub Pages    │      │  边缘代理层         │      │  公开列表 / 音频流 │
│  静态站 + 索引数据 │ ───▶ │  （Deno Deploy）   │ ───▶ │                  │
│  index/tracks    │      │  会话池 · 实时转发   │      │   来源站          │
└─────────────────┘      └───────────────────┘      └──────────────────┘
```

- **前端**：纯静态（HTML + CSS + 原生 JS，无框架无构建步骤），曲目索引内嵌于 `index.html` 与 `tracks.json`。
- **代理层**：部署在边缘运行时（Deno Deploy）的轻量转发服务——维护免登录会话池，按访客来源哈希自动分配授权，实时转发音频流；无注册/登录界面，整站零跳转。
- **自动更新**：GitHub Actions 每日定时执行「抓取 → 分类 → 清洗 → 构建 → 推送」，Pages 自动重新部署。

## 功能

- **首页**：统计卡片 + 分类入口 + 最新入库 30 首
- **分类浏览**：单曲 / 串烧 / 中文 / 英文组合筛选
- **全部曲目**：客户端分页（每页 50 首），格式/语言下拉筛选
- **搜索**：基于文件名关键词的客户端模糊搜索，大小写不敏感
- **日期归档**：700+ 个入库日期网格，点击查看当天全部曲目
- **页内试听**：不跳转，页内**科技风波纹播放器**（Canvas 动态波形 + 播放/暂停 + 点击波形跳转进度），播放源由代理层实时转发
- **一键下载**：点击即下载 MP3（文件名保持原始文件名），无需注册登录
- **下载文件 ID3 品牌化**：写入 9GDJ.com 品牌标签——**艺术家 / 唱片集 / 流派**替换为品牌信息（唱片集固定为 `9GDJ.com`），**标题保留原文件原有值不做替换**
- **移动端适配**：卡片化布局、整卡点击、首屏懒加载、滚动位置记忆
- **PWA**：可安装到桌面/主屏，Service Worker 缓存静态资源（缓存名随构建自动版本化，保证用户拿到最新版）

## 分类规则

### 单曲 / 串烧

**主规则：文件大小 ≥ 100 MiB → 串烧；否则 → 单曲。**

**辅助规则：** 文件名含以下关键词之一也归为串烧（不受大小限制）：

`串烧`、`mashup`、`mash up`、`mixset`、`megamix`、`连续串`、`大串烧`、`串烧版`、`连续播放`

阈值与关键词可在 `scripts/classify.py` 顶部调整。

### 中文 / 英文

- 文件名含中文字符（Unicode `\u4e00-\u9fff`）→ **中文**
- 否则含拉丁字母（A-Za-z）→ **英文**
- 两者均无 → **其他**

### 每日最新

按入库时间（YYYY-MM-DD）分组，首页展示最新入库，日期归档页可按天浏览。

## 项目结构

```
├── .github/workflows/     # GitHub Actions：每日自动抓取/分类/清洗/构建/部署
├── scripts/
│   ├── scrape.py          # 抓取公开列表新增曲目（并发、重试、断点续爬）
│   ├── classify.py        # 分类：串烧/单曲 + 中文/英文 + 统计
│   ├── clean_bad.py       # 清洗空文件名/零大小脏数据，重算统计
│   └── build_site.py      # 静态站点生成器（HTML/CSS/JS/tracks/dates/PWA）
├── deno-server/           # 边缘代理层源码（会话池 + 音频流转发 + ID3 品牌标签）
├── pwa-assets/            # PWA 清单、Service Worker 模板、图标
├── site/                  # 构建产物 → 部署到 GitHub Pages
│   ├── index.html
│   ├── assets/
│   ├── data/              # tracks.json / stats.json / dates.json
│   └── sw.js / manifest.webmanifest
└── README.md
```

## 本地运行

**1. 抓取 / 分类 / 清洗 / 构建（与 Actions 同一流水线）**

```bash
python scripts/scrape.py       # 抓取新增曲目（断点续爬不重复）
python scripts/classify.py     # 分类（大小阈值 + 关键词 + 语言）
python scripts/clean_bad.py    # 清洗脏数据并重算统计
python scripts/build_site.py   # 重建站点（site/ 目录）
```

**2. 本地预览**

```bash
cd site
python -m http.server 8000
# 浏览器打开 http://localhost:8000
```

> 本地预览时搜索/浏览/日期归档均可用；试听/下载需要代理层（本地未部署代理时可用线上站点体验完整功能）。

## 自动更新（GitHub Actions）

仓库内置 `daily-scrape-update` 工作流，**每日自动**执行：

```
抓取新增 → 分类 → 清洗 → 重建站点 → 推送 → Pages 自动部署
```

无需人工干预。也可在 Actions 页面手动触发 `Run workflow`。

## 部署

1. **GitHub Pages**：仓库 Settings → Pages → Source 选择 `Deploy from a branch` → `main` / `/root`（site 内容位于仓库根，或按实际目录配置）。
2. **代理层**：将 `deno-server/` 部署到边缘运行时（Deno Deploy），并把前端 `API_BASE` 指向代理域名（构建时写入 `build_site.py`；本地自动走 `localhost` 空值）。

## 技术栈

- 抓取/清洗/构建：Python 3 + requests + BeautifulSoup4 + lxml
- 前端：纯静态 HTML + CSS + 原生 JavaScript（无框架）
- 代理层：Deno（边缘运行时）
- 部署：GitHub Pages + GitHub Actions
